## Measured-vs-binary conflicts worth a re-recording (cheap, high value)

1. Sandbox duck time: the spec says 0.4 s (27 ticks). The binary uses the per-player DuckSpeed, and `player_sandbox.lua` sets 0.1. Either the recording used the base class (a `bot` without the sandbox player class applied?) or the field was not set on the bot. Record `Player:GetDuckSpeed()` in the probe.
2. Fall thresholds: binary comparison chain = 350 (punch) / 290 (0.85 step) / 580 (damage, 1.0 step) with SDK values; recordings say 526.5 hurts and 342 punches. Both cannot hold with the SDK numbers; the constants are unresolved anonymous floats, so GMod may have changed them to the HL1-branch set (303 / 263.25 / 526.5) - that set fits the recordings exactly (342 >= 303 punches, 191.5 does not; 526.5 hurts). Treat **303 / 263.25 / 526.5** as the likely GMod values; one landing at 290-300 u/s settles it.
3. Noclip constants (speed factor, sprint x3 vs measured 1000, duck factor).
4. Swim-sound period 500 vs 1000 ms.

## Things we do that the game does not

- Engine-level forward jump boost for every player (`jump_boost`, gm-move 979-998): the game's engine has none; only the sandbox player class adds it in Lua, with a velocity-sign rule.
- Noclip acceleration and friction glide (`noclip`, 1112-1143): the game sets the velocity directly.
- Fitted ground-reach constants `ground_probe 1.2`, `world_ground_probe 1.0`, `ENTITY_GROUND_REACH 0.4`, `PROP_SKIN 0.5` (25-29, 104-105): the game has one geometric rule (+2 / -1 u, lower-half hull); the prop skin is a vphysics artefact we emulate.
- Always-on "rising > 140 u/s drops the ground" (`NON_JUMP_VELOCITY`, 712): off in the game with `sv_sticktoground 1`.
- `StayOnGround` threshold `0.5 * DIST_EPSILON` (827): the game uses a fixed 0.5 u.
- Air friction factor 0.25 chosen purely from the sign of the vertical velocity (475, 509): the game sets it only after a steep-surface probe.
- Instant eye height switch on duck (`eye_height_of`): the game interpolates.
- `ground_push` / `phys_lift` flags on the player (`categorize` 712-721): our own bookkeeping for physics pushes, no game equivalent (the game gets the same effect from base velocity and `SetGroundEntity`).
- `ducked_at_tick_start` crouch-speed rule (1012): equivalent to the game's start-of-move FL_DUCKING check, fine, but it is a model, not the mechanism.
