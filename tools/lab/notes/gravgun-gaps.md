## Things we do that the game does not
- **Orange dynamic light while holding** (`main.rs:5499-5505`, radius 128): the game's physcannon never allocates a dlight; the only light is the additive sprites.
- **Snapping the carried prop to 90° orientations** (`pickup.rs:156-178` via `Carry::new`): gravgun carries keep the grab-time orientation (the game only snaps for +USE).
- **Zeroing velocity on drop** (`lib.rs:11320-11323`): the game clamps to 285 u/s / 720 °/s.
- **Pull reaching 4096 u** (`weapons.rs:277`): the game stops at 1000 u.
- **Pulling every tick** (`weapons.rs:732-734`): the game pulls once per 0.1 s.
- **Core sprite always drawn** at scale 6 (`main.rs:5473-5476`): in the CLOSED state the game shows the core at the READY value only after a target was seen; after `StopEffects`/holster everything is hidden; with no target the core still shows at 14/128 (READY) — but the glows flicker at 16..24 alpha, far dimmer than our constant full-bright 4 u dots.
- **Punting frozen props is refused** (`lib.rs:11242`): the game punts them (unfreeze through the pickup rules).
- **Playing `TooHeavy` on every press** (`lib.rs:11276-11279`): the game latches it once until the claws cycle.

- `vphysics/` and `luashared/` directories were absent from the archive, so `ComputeShadowControl`, `PhysComputeSlideDirection` and the Lua-side glue could not be read (SDK formulas assumed; the Rust physgun already fits a shadow controller).
- The client `PhyscannonImpact` callback and `DoEffectLaunch` were not among the 830 client functions; their SDK HL2MP values are reported with medium confidence.
- Several float constants are unnamed data in the binary (`maxAngular`, drop clamps, pull `0.5/50`, endcap/holding scales); the values reported are the SDK's where the code shape matched exactly.
