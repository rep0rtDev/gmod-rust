# Toolgun / sandbox C++ side — behaviour note

Subsystem: `toolgun` (gmod_tool, gmod_camera, scripted entities SENT, scripted weapons SWEP, client Lua effects).
Sources used: Ghidra pseudo-C of the user's GMod binaries (server_srv.so with symbols: 238 functions — the five scripted-entity bridge classes, their factories and the Lua effect script manager; client.dll without symbols: 830 functions selected by the RTTI vtables of the client effect / scripted-entity classes and their callees), the sandbox and base gamemode Lua from Facepunch/garrysmod, Source SDK 2013 (`basecombatweapon_shared.cpp`, `baseentity.cpp`) for cross-checks, and the Rust repo's own srcds goldens (`docs/spec/script.md`, golden 261031) for the two think constants that live in rodata outside the dump.

Tags: every fact ends with `[src: …; conf: high|medium|low]`. `pseudo-C` = read in the dump (server = symbol names available, client = vtable slot); `Lua` = Facepunch Lua file; `SDK` = Source SDK 2013; `golden` = the Rust repo's srcds measurements; `inference` = derived.

Important scoping fact first:

- F1. The toolgun and the camera are **Lua SWEPs** of the sandbox gamemode (`gmod_tool`, `gmod_camera`); there is no C++ toolgun class. The C++ side that matters is the scripted-weapon/entity bridge (how `PrimaryAttack`, `Think`, `Initialize`… reach Lua), the effect bridge, and the engine weapon loop. The dump contains the scripted-entity (SENT) bridge and the effect manager but **not** the scripted-weapon (SWEP) bridge class, so the engine-side fire gating is reconstructed from Lua + SDK + goldens (see F20-F27 and Blockers). [src: INDEX.txt + pseudo-C strings; conf: high]

[src: Lua `gmod_tool/shared.lua`; conf: high]

[src: Lua shared.lua; conf: high]

- F5. Network vars: `Stage` (NWInt), `Op` (NWInt), plus the current mode string read from the owner's userinfo convar `gmod_toolmode` (archive, userinfo, default `"rope"`). [src: Lua shared.lua / stool.lua / object.lua; conf: high]

## 2. Fire rate and input gating

- F8. `gmod_tool` never calls `SetNextPrimaryFire` / `SetNextSecondaryFire`, so the engine's next-attack times stay at their initial value (0) and never block a click. [src: Lua shared.lua, grep; conf: high]
- F9. Engine weapon loop (per player command, every tick while the weapon is active): the SDK fires `PrimaryAttack` whenever `IN_ATTACK` is **held** and `next primary attack <= curtime`, and `Reload` when `IN_RELOAD` is held (SDK `ItemPostFrame`, lines ~1758 and ~1803). GMod's weapon bridge adds the `Primary.Automatic` / `Secondary.Automatic` gates: with `Automatic = false` the attack is only forwarded on the tick the button was **pressed** (edge), with `Automatic = true` on every tick it is held. [src: SDK; GMod gate = Lua convention + golden `lua_swep` ("five automatic primaries 14 ticks apart" only because that SWEP set a 0.2 s next-fire), SWEP bridge absent from dump; conf: medium]
- F10. Resulting toolgun cadence: a non-automatic stool fires once per mouse press (no cooldown at all between presses, i.e. limited only by the 66.67 Hz command rate); an automatic stool (`LeftClickAutomatic = true`) fires **every tick** (66.67/s at `tickrate 66`) while held unless the stool itself rate limits (e.g. the inflator/paint do nothing per tick but apply a frame-time-scaled change). [src: inference from F8-F9; conf: medium]
- F11. `Reload` is semi-automatic by Lua: it returns unless `owner:KeyPressed(IN_RELOAD)` this tick. [src: Lua shared.lua; conf: high]
- F12. Deploy block: the weapon's first `Think` after being selected comes 14 ticks (0.2 s deploy delay) after the select; `Deploy` itself calls `tool:UpdateData()` (stage := number of stored objects) and `tool:Deploy()`. [src: golden `lua_swep_think`; Lua shared.lua; conf: high]
- F13. Prediction: `PrimaryAttack` / `SecondaryAttack` / `Reload` run on both server and client (shared realm); the effects/sound branch is guarded by `IsFirstTimePredicted()` so a re-prediction does not double the effect. [src: Lua shared.lua; conf: high]

## 3. Click handling — hook order

- F14. Left click, exact order (same shape for right click with `RightClick` and reload with `Reload`):
  1. `DoToolTrace()` — nil → return (nothing at all happens, no sound);
  2. `GetToolObject()` — nil → return;
  3. `tool:CheckObjects()` — drops every stored object if any stored non-world entity became invalid (then stage/op reset to 0);
  4. `tool:Allowed()` — `toolmode_allow_<mode>` 0 → return;
  5. gamemode hook `CanTool(player, trace, mode, toolObject, button)` with button 1 = left, 2 = right, 3 = reload; false → return. Sandbox's default `CanTool` asks the hit entity's `ENT:CanTool(ply, tr, mode, tool, button)` and `CanTool` gamemode hooks;
  6. `tool:LeftClick(trace)` / `RightClick` / `Reload`; a return other than true → return (nothing visible);
  7. `DoShootEffect(hitpos, hitnormal, entity, physbone, IsFirstTimePredicted())`.
  [src: Lua shared.lua; conf: high]
- F15. `DoShootEffect`: `EmitSound("Toolgun.Single")`; `SendWeaponAnim(ACT_VM_PRIMARYATTACK)`; `owner:SetAnimation(PLAYER_ATTACK1)`; then only if first-time-predicted **and** the client convar `gmod_drawtooleffects` is non-zero: `util.Effect("selection_indicator", {Origin = hitpos, Normal = hitnormal, Entity = ent, Attachment = physbone})` then `util.Effect("ToolTracer", {Origin = hitpos, Start = owner:GetShootPos(), Attachment = 1, Entity = weapon})`. Sound and animations play regardless of the convar. [src: Lua shared.lua; conf: high]
- F16. Base `TOOL` defaults: `LeftClick`/`RightClick` return false (no effect, no sound), `Reload` clears the objects and returns false; `Deploy`/`Holster`/`Think` are no-ops, `FreezeMovement` false, `DrawHUD` and `DrawToolScreen` nil (screen falls back to the scrolling text). [src: Lua stool.lua; conf: high]
- F17. `Think` of the weapon (every tick on both realms while active; client skips the frame it was holstered on): read mode from userinfo; `tool:CheckObjects()`; if mode changed: old tool `ReleaseGhostEntity()` + `Holster(true)` *(the 'true' marks a tool switch)*, new tool `Deploy(true)`; if the new tool is not allowed: holster it and return; copy the `Automatic` flags (F3); `tool:Think()`. [src: Lua shared.lua; conf: high]
- F18. Weapon `Holster(nextWeapon)`: `tool:Holster()`, result nil counts as true (`CanHolster`), remembers the client frame for F17, releases the ghost. `OnRemove` and `OwnerChanged` release the ghost. [src: Lua shared.lua; conf: high]
- F19. Tool object state: `Stage` and `Op` are the weapon's NWInts (server authoritative, client reads); `Objects[i] = {Ent, Phys, Bone, Pos(local), Normal(local)}`; for the world (entindex 0) `Pos`/`Normal` are stored in world space; otherwise relative to the physics object if present (`WorldToLocal`, `WorldToLocalAngles(Normal:Angle()):Forward()`), else to the entity. `ClearObjects` resets stage and op to 0. `GetPos/GetNormal/GetEnt/GetPhys/GetBone` convert back. [src: Lua object.lua; conf: high]

## 4. The tool trace

- F20. `DoToolTrace`: start = owner's eye position (`GetPlayerTrace`), direction = eye angles forward, length = `MAX_TRACE_LENGTH` (56756 u, the engine's default for `GetPlayerTrace`), mins = maxs = (0,0,0), mask = `CONTENTS_SOLID | MOVEABLE | MONSTER | WINDOW | DEBRIS | GRATE | AUX` (hits players/NPCs via MONSTER, windows, debris props, grates; not water, not the clip/playerclip brushes), filter = {owner, owner's vehicle}. [src: Lua shared.lua; conf: high]
- F21. First a line trace. If it did not hit, or hit nothing with a valid entity (`IsValid(tr.Entity)` false — the world counts as *valid* here only when `tr.Hit` and `tr.Entity` is the worldspawn entity, which `IsValid` returns true for), a second **hull** trace with the same zero-size hull is run (`util.TraceHull`); if that one hits a valid entity its result replaces the line trace and `trace.HullTrace = true` is set. If after that `tr.Hit` is false, nil is returned (no click). The zero-size hull trace differs from the line trace only in how the engine treats start-solid and the collision model (hull traces test against the entity's collision bounds / vcollide the same way; props in `SOLID_VPHYSICS` hit on their PHY hulls, not the studio box). [src: Lua shared.lua; conf: high for the sequence, medium for the hull-trace difference]
- F22. Entities with no physics object (brush entities etc.) have `PhysicsBone 0`; the toolgun passes `trace.PhysicsBone` to `DoShootEffect` as the effect `Attachment` and to `SetObject` as `Bone`. [src: Lua; conf: high]

## 5. Ghost entity

- F23. `MakeGhostEntity(model, pos, ang)`: only on the first-time-predicted pass; models that are not valid props (ragdolls, effects via `util.IsValidProp`) are refused; in single player the ghost is a server `prop_physics`, in multiplayer a client-side prop (`ents.CreateClientProp`); it gets `PhysicsDestroy`, `MOVETYPE_NONE`, not solid, `RENDERMODE_TRANSCOLOR`, color (255,255,255,150), `DoNotDuplicate = true`. [src: Lua ghostentity.lua; conf: high]
- F24. `UpdateGhostEntity` (used by weld/axis style tools): angles = `Phys:AlignAngles(Normal1:Angle(), (-HitNormal):Angle())`-style alignment (first stored normal to the flipped hit normal), position = `HitPos + (entityOrigin - LocalToWorld(storedLocalPos)) + HitNormal` (1 u out along the normal); hidden when there is no trace / the trace hits the ghost's own prop. [src: Lua ghostentity.lua; conf: high]

## 6. The screen texture animation

- F25. What drives it: the weapon's client `RenderScreen()` callback, which the engine calls **once per rendered frame** for the active weapon's view model (hook `RenderScreen` exists on SWEPs; no tick coupling). The frame rate of the animation is therefore the client's render frame rate; the content is a function of wall-clock time. [src: Lua cl_viewscreen.lua + Lua SWEP API; conf: high]
- F26. Render target `GModToolgunScreen`, 256×256 (`TEX_SIZE`); the view model's material `models/weapons/v_toolgun/screen` gets its `$basetexture` replaced by this render target (so the material is unlit; the game's VMT is `UnlitGeneric`). Each frame: push RT, `cam.Start2D`, draw background texture `models/weapons/v_toolgun/screen_bg` full size (256×256, white), then either `TOOL:DrawToolScreen(256, 256)` if the stool defines it, else the default text. [src: Lua cl_viewscreen.lua; conf: high]
- F27. Default text: font `GModToolScreen` = Helvetica, size 60 px, weight 900; string = language string `#tool.<mode>.name`; `w = textWidth + 64` (px); `x0 = -((RealTime() * 250) mod w)` (scroll **left at 250 px/s**, period `w` px, using `RealTime()` = wall clock, so it keeps scrolling while the game is paused or the player is dead); `y = 104 - textHeight/2` (vertically centred on y = 104); for `x = x0; x < 256; x += w`: draw the text at `(x+3, y+3)` in black then at `(x, y)` in white. No clearing besides the background blit; no interpolation. [src: Lua cl_viewscreen.lua; conf: high]

## 7. Sounds

- F28. Click: sound script `Toolgun.Single` (sandbox `scripts/game_sounds_*`), emitted on the weapon entity by `DoShootEffect` **only when the stool returned true** (F14 step 6). A refused click (`CanTool` false, stool returned false, trace miss) is silent. [src: Lua; conf: high]
- F29. The camera's shot sound is `NPC_CScanner.TakePhoto` (F38). There are no other toolgun-weapon sounds; stools emit their own (e.g. leafblower `ambient/wind/wind_hit2.wav`). [src: Lua; conf: high]

## 8. Click effects (client Lua effects)

- F30. `ToolTracer` (base gamemode `effects/tooltracer.lua`), material `effects/tool_tracer`: `StartPos = GetTracerShootPos(data.Start, weaponEntity, attachment 1)` (the view model's muzzle attachment for the local player in first person, the world model's attachment 1 otherwise, `data.Start` as fallback), `EndPos = data.Origin` (the hit point); render bounds = world-space box (StartPos, EndPos); `Life = 0, Alpha = 255`. `Think`: `Life += FrameTime() * 4` (dies when `Life >= 1`, i.e. **0.25 s** lifetime), `Alpha = 255 * (1 - Life)`. `Render` (skipped once Alpha < 1): one random texcoord `u ∈ [0,1)` per frame; `norm = (StartPos - EndPos) * Life`; three identical beams `DrawBeam(StartPos - norm, EndPos, width 8, u, u + |norm|/128, white)` — the beam's start slides from the muzzle towards the hit point over the 0.25 s — plus one full beam `DrawBeam(StartPos, EndPos, 8, u, u + |Start-End|/128, Color(255,255,255, 128*(1-Life)))`. [src: Lua tooltracer.lua; conf: high]
- F31. `selection_indicator` (sandbox): material `effects/select_dot`; render bounds ±8; position = hit point; angles = `Normal:Angle() + Angle(0.01,0.01,0.01)`; if the hit entity is valid: `SetParentPhysNum(attachment = physbone)` then `SetParent(ent)` (so the dot rides a ragdoll bone / prop); `Size = 4`, `Alpha = 255`; spawns **six** `selection_ring` effects with the same data. `Think`: `Alpha -= 255 * FrameTime()` (**1.0 s** life). `Render`: `DrawQuadEasy(pos, angles:Forward(), 4, 4, Color(255,255,255,Alpha))`. [src: Lua selection_indicator.lua; conf: high]
- F32. `selection_ring` (sandbox): material `effects/select_ring`; collision bounds ±8; position = hit point + normal × 2; same angle rule; parented the same way; `Speed = Rand(0.5, 1.5)`; `Size = 4`, `Alpha = 255`. `Think`: `Alpha -= FrameTime() * 255 * 5 * Speed` (life 0.2/Speed s = 0.133…0.4 s), `Size += FrameTime() * 256 * Speed` (grows 128…384 px/s). `Render`: `DrawQuadEasy(pos, forward, Size, Size, Color(Rand(10,150), Rand(170,220), Rand(240,255), Alpha))` — a flickering blue-cyan ring, new random colour every frame. [src: Lua selection_ring.lua; conf: high]
- F33. Client effect lifecycle (C++): `util.Effect` creates a client entity object (full animating entity: it has position, angles, model, render bounds, parent, can be parented to a bone, sets `self.Entity = self`); the bridge calls Lua `Init(effectData)` — if `Init` returns false (or errors) the engine prints `Error: Couldn't initialize effect!` and removes the effect; after `Init` the bridge **caches** the table's `Render`, `Think`, `StartTouch`, `Touch`, `EndTouch`, `PhysicsCollide` functions (changing them later on the instance has no effect). `Think` is called every frame; returning anything but true removes the effect; `Render` is called from the translucent renderables pass when the render bounds are visible (so an effect with wrong bounds is culled). `PhysicsCollide` passes the same data table as the server SENT (F55) and only happens for effects that initialised physics. [src: client pseudo-C (effect init slot, think/render slots, collision dispatcher); conf: high for init/caching/error string, medium for the frame cadence (standard client entity think)]
- F34. Effect script loading (server side): on gamemode load `effects/base.lua` is loaded first, then every directory under `effects/*`; a name without `.lua` maps to `effects/<name>/init.lua`, a bare file `effects/<name>.lua` is used as-is; names are lower-cased; each file is registered for client download (`AddCSLuaFile`-equivalent tagged `!EFFECT`). The server never executes effect bodies. [src: server pseudo-C (effect manager, 2 functions); conf: high]
- F35. `camera_flash` (sandbox, used by gmod_camera in multiplayer): a dynamic light keyed by the entity index at `data.Origin`: rgb 255/255/255, brightness 10, size 512, decay 512, `DieTime = CurTime() + 0.02` (one tick); `Think` returns false (one-frame effect); no `Render`. [src: Lua camera_flash.lua; conf: high]

[src: Lua; conf: high]

## 11. Scripted entity (SENT) bridge — server (`server_srv.so`, symbols)

Five C++ classes exist: anim, point, brush, filter, AI; each wraps a Lua table and forwards virtuals. `GetLuaEntityType` returns 1 (= "entity") for anim/point/AI. [src: pseudo-C; conf: high]

- F42. **Spawn (anim)**: reads the model name from the Lua object, precaches it, sets it; if the model is missing or its studio header fails to load the model becomes `models/error.mdl`; base animating spawn; think function := script think, **next think = now + T_A**; then `precache allowed := true`, Lua `Initialize()`, flag restored. `KeyValue("ScriptName")` sets the class before that. [src: pseudo-C; conf: high; T_A value: see F45]
- F43. **Spawn (point)**: point spawn, think = script think, next think = now + T_A, `Initialize` the same way. **Spawn (brush)**: trigger spawn, next think = now + T_A, `InitTrigger`, trigger enabled, `Initialize`. **Spawn (AI)**: Lua `CreateSchedulesInternal()` is called **before** `Initialize()`, then base combat-character spawn, think = script think at now + T_A; model fallback `models/error.mdl` at the end. [src: pseudo-C; conf: high]
- F44. **Script think (anim/point/brush)**: calls Lua `Think()`; if it returns nothing / false → next think = now + T_B (the "default cadence"); if it returns true → no automatic reschedule (the entity must have called `NextThink`). anim only: afterwards, if the Lua table field `AutomaticFrameAdvance` is true → studio frame advance + dispatch animation events; if a transmit flag is set → `DispatchUpdateTransmitState`. **AI**: first an "expression finished" callback (pushes the expression name), NPC think, then Lua `Think()`; no return → next think = now + **T_A** (the AI class reuses the first-think constant), then frame advance. The server-side `ClientThink` of the point class just calls `Think` without rescheduling. [src: pseudo-C; conf: high]
- F45. T_A and T_B are doubles in rodata (not in the dump). Measured on srcds: first `Think` 7 ticks after spawn (≈0.1 s) then every 13 ticks (≈0.2 s) when `Think` does not reschedule → **T_A = 0.1 s, T_B = 0.2 s**. These are GMod additions: SDK entities have no default think interval (a think runs once unless `SetNextThink` is called). [src: golden `lua_sent`; SDK; conf: high for the values, medium that AI = 0.1]
- F46. `UpdateTransmitState` (anim): if the "attached to parent" flag is set → copy the parent's transmit state (masked to the three state bits), or PVS when the parent is invalid; else Lua `UpdateTransmitState()`: 0 → ALWAYS, 1 → PVS, anything else → NEVER; **no return → ALWAYS** for anim, **PVS** for point. [src: pseudo-C; conf: high]
- F47. `KeyValue(key, value)`: `ScriptName` (case-insensitive) sets the script class; then Lua `KeyValue(key, value)` (return ignored); then the base `KeyValue` **always** runs too. [src: pseudo-C; conf: high]
- F48. `AcceptInput(name, activator, caller, value)`: Lua gets the value typed (int → number, string → string, NULL string → "", float → number, bool → bool, other → nil); Lua returning **true** consumes the input (base skipped); otherwise base `AcceptInput`. vprof node `SENT:AcceptInput`. [src: pseudo-C; conf: high]
- F49. `Use`: Lua `Use(activator, caller, useType, value)` (4 args) unless the entity is marked for deletion. `StartTouch/Touch/EndTouch/Blocked(other)`: one entity argument, return ignored. [src: pseudo-C; conf: high]
- F50. `OnTakeDamage(dmginfo)`: Lua is called; the C++ returns the number Lua returned (0 if none) and does **not** call the base class — health is not decremented by C++ for a SENT (the script must do it). `TraceAttack(dmginfo, dir, trace)`: Lua first, base always after. [src: pseudo-C; conf: high]
- F51. `DoImpactEffect(trace, damageType)` and `ImpactTrace(trace, damageType, customImpactName or "")`: Lua returning true suppresses the engine impact effect / trace. `HandleAnimEvent(event, eventTime, cycle, type, options or "")`: Lua returning a boolean true suppresses the base handler. [src: pseudo-C; conf: high]
- F52. `TestCollision(startPos, delta, isBox, extents, mask)` (startPos = ray start + offset, isBox = not a ray): Lua returning a table → the trace gets `Fraction`, `HitPos`, `Normal` from it, hit entity = this entity, hitbox 0, hitgroup 0, not start-solid; returning true → default handling; anything else → no collision. Default handling by solid type: `SOLID_BBOX` (2) → ray vs the entity OBB at its origin; `SOLID_VPHYSICS` (6) → ray vs the vcollide of the entity's physics object with the model's contents mask, surface props filled in; otherwise base animating. [src: pseudo-C; conf: high]
- F53. `PhysicsSolidMask`: if the Lua table has a numeric `PhysicsSolidMask` it is used, else the base mask. (Client has the same field read.) [src: pseudo-C server+client; conf: high]
- F54. `VPhysicsCollision`: the base collision handling (physics impact sounds/effects/damage) runs **only if** the Lua table field `PhysicsSounds` is true; then Lua `PhysicsCollide(data, physObj)` is called when this or the other entity is `SOLID_VPHYSICS` and the entity is not being deleted; a global "inside physics callback" flag is held during the call. [src: pseudo-C; conf: high]
- F55. `PhysicsCollide` data table keys: `DeltaTime`, `Speed`, `OurSurfaceProps`, `TheirSurfaceProps`, `OurOldVelocity`, `TheirOldVelocity`, `OurNewVelocity`, `TheirNewVelocity`, `OurOldAngularVelocity`, `TheirOldAngularVelocity`, `HitEntity`, `HitObject`, `PhysObject`, `HitNormal`, `HitPos`, `HitSpeed` (from the real collision event; surface props are the surface-property indices). The same table is built on the client for effects/clientside SENTs. [src: pseudo-C server + client strings; conf: high]

- F57.
